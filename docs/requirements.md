# Требования: Granny Square Color Planner

## Цель

Веб-приложение для планирования цветовой комбинации «бабушкиного квадрата»
(granny square) при вязании крючком. Пользователь собирает квадрат ряд за
рядом, красит ряды из своей палитры и сохраняет готовые комбинации для
сравнения.

## Источник

Макет: [docs/reference/main-screen.pdf](reference/main-screen.pdf). Красный
текст на макете — пояснения автора макета, не элементы интерфейса.

## Функциональные требования (MVP)

### Рабочий квадрат

- Отображается как концентрические ряды («слои»), от центра к краю.
- По умолчанию создаётся с 7 рядами, без цвета (нейтральный/пустой вид).
- Кнопка «Добавить слой» добавляет один новый ряд снаружи.
- Клик по ряду открывает контекстное меню рядом с курсором с двумя пунктами:
  - «Изменить цвет»
  - «Удалить» — удаляет этот ряд из квадрата.

### Изменение цвета ряда

- Пункт «Изменить цвет» открывает небольшое немодальное окно поверх экрана
  (главный квадрат остаётся видимым и не блокируется).
- В окне палитра отображается сердечками с цветом заливки.
- Клик по сердечку сразу применяет цвет к выбранному ряду на главном
  квадрате (живое превью), выбранное сердечко помечается галочкой.
- Кнопка «Сохранить» фиксирует применённый цвет и закрывает окно.
- Кнопка «Закрыть» закрывает окно без сохранения — ряд возвращается к
  цвету, который был до открытия окна.

### Палитра цветов

- Отображается справа от рабочего квадрата, цвета — в виде сердечек.
- Кнопка «Добавить цвета» открывает форму: поле «Цвет» (hex, например
  `#A3D8F4`), кнопки «Сохранить» (добавляет цвет в палитру) и «Удалить»
  (очищает поле/отменяет ввод).
- У каждого сердечка в палитре — крестик в верхнем правом углу; клик по
  нему удаляет цвет из палитры.
- Валидация: принимается только корректный hex-цвет (`#RGB` или `#RRGGBB`).

### Сохранённые комбинации

- Кнопка «Сохранить» рядом с квадратом сохраняет текущую раскраску всех
  рядов как комбинацию.
- Сохранённые комбинации отображаются ниже квадрата мини-превью того же
  вида (концентрические ряды), в виде сетки.

### Хранение данных

- Палитра цветов и сохранённые комбинации хранятся в `localStorage` и
  переживают перезагрузку страницы.
- Состояние самого рабочего квадрата (количество рядов и их текущие цвета)
  также сохраняется в `localStorage`, чтобы не терять работу при
  обновлении страницы — это минимальное дополнение к макету, решение
  принято ради UX и не скрывается.

## Нефункциональные требования

- Стек: React + TypeScript, стилизация — Tailwind CSS.
- Без бэкенда, всё состояние — на клиенте.
- Никаких `any` и `as` в TypeScript-коде (валидация через type guards).
- Комментарии в коде — не длиннее 2 строк, только там, где не очевидно из кода.
- Минимум зависимостей.
- Дизайн милый (скруглённые формы, сердечки, мягкая типографика), но
  нейтральный по цвету — интерфейс не должен визуально спорить с цветами,
  которые подбирает пользователь (никаких ярких фирменных цветов на
  кнопках/фоне, только нейтральная палитра UI + акцент через форму, не
  через цвет).

## Вне рамок MVP (бэклог, с макета — зелёным)

- Экспорт цветовой комбинации.
- Раскладка кардигана из квадратов.
- Калькулятор расхода пряжи.

Эти пункты не реализуются сейчас, но архитектура не должна им мешать.
